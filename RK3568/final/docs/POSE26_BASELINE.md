## Native OCR 与 OpenCV resize

- 实现提交：`2c9a8eeecb5f0ac32e3692e24b276c00d3f8f6d6`（`perf(ocr): fuse native inference and decoding`）
- OCR resize 最终保留 `cv2.resize(..., (168, 48), INTER_LINEAR)` 和 BGR 通道顺序。
- 曾验证 RGA BGR resize 的通道、stride 和缓冲边界，但板上 RGA 与 OpenCV 的插值取整差异导致 11 个现有候选中 2 个文字变化，因此按最终决定撤销 RGA OCR resize，不进入提交。
- Native C 接收固定 `168×48 BGR`，复用持久 uint8、float32 和输出缓冲，以 NHWC float32 执行 RKNN，并在 C 中完成稳定 softmax、21步 CTC 去重/去空白和5类内部颜色解码。
- Python 只负责 OpenCV resize 和字符索引映射；`recognize_rknn()` 的四元组返回契约不变。`python-toolkit` 后端继续使用相同 OpenCV BGR resize 和 Python 解码。

板上现有图片共 11 个候选逐项比较结果：文字 11/11 完全一致，内部颜色 11/11 完全一致，文字和颜色置信度最大绝对误差均不超过 0.05，没有新增空结果或异常。1100 次交错采样结果如下：

| 路径 | OCR 墙钟 P50 | OCR 墙钟 P95 | OCR 墙钟 P99 |
|---|---:|---:|---:|
| 迁移前：OpenCV + 通用 Native RKNN + Python 解码 | 4.254ms | 4.623ms | 4.770ms |
| 迁移后：OpenCV + Native RKNN/CTC/颜色融合 | 3.246ms | 3.508ms | 3.605ms |

迁移后 OCR 墙钟 P95 下降 24.13%。融合路径内部 P95 为：OpenCV resize 0.276ms、Native 输入/NPU/输出 2.737ms、Native 解码 0.067ms、OpenCV resize 加 C 内总计 3.058ms。由于最终不采用 RGA，原计划的“RGA resize P95 低于 OpenCV”条目不再适用。
